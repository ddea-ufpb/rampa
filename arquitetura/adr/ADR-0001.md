# ADR-0001 Usar FastAPI para a API Principal

**Status:** aceita
**Contexto:** O sistema necessita de "ingestão concorrente de relatos" e manipulação de "consultas geoespaciais sob volume" com prazo curto (MVP 60h). O nível de conhecimento em backend é baixo, mas há familiaridade teórica com a leitura de código em Python.
**Opções consideradas:**
*   Flask: Simples, mas síncrono por padrão e exige bibliotecas de terceiros para validação e documentação.
*   Node.js (Express): Excelente para concorrência, mas diverge do conhecimento principal focado em Python.
*   FastAPI: Assíncrono nativo, gera documentação (Swagger) automática e possui validação forte via Pydantic, favorecendo a geração de código por agentes LLM.
**Decisão:** Utilizaremos o FastAPI em conjunto com o Python.
**Consequências:** 
*   **(+) boas:** Resolução nativa de concorrência com rotas `async`, validação estrita que evita falhas de segurança na inserção de Lat/Lng, melhor aproveitamento do agente LLM (PAUL).
*   **(-) ruins:** Curva de aprendizado inicial sobre tipagem estática (Pydantic) e *async/await*.
