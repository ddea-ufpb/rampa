# ADR-0003 Usar Redis para Gerenciar a Ingestão Concorrente

**Status:** aceita
**Contexto:** O projeto estipula explicitamente o uso de um componente concorrente: "Ingestão concorrente de relatos + fila de moderação + fan-out de atualizações". Acessar o banco de dados diretamente sob picos de ingestão pode travar o serviço.
**Opções consideradas:**
*   Banco de Dados (Tabelas de Fila): Lento e propenso a falhas de travamento (*table locks*) na concorrência pesada.
*   RabbitMQ / Kafka: Complexos demais para o contexto acadêmico de 60 horas.
*   Redis: Extremamente rápido, em memória, fácil de usar como intermediário de filas (*message broker*) com Python.
**Decisão:** Utilizaremos Redis como um *buffer* na camada de concorrência e filas.
**Consequências:** 
*   **(+) boas:** Garante que N relatos submetidos ao mesmo tempo sejam enfileirados sem perda de dados (vivacidade e segurança).
*   **(-) ruins:** Adiciona um novo contêiner à infraestrutura local (Docker).
